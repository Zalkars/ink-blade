# Ink Blade: общий Godot-проект для Windows и Android

## Решение

Порт строится как один проект Godot 4.x. Из него будут экспортироваться две
сборки:

- Windows — для разработки, клавиатуры и геймпада;
- Android — для сенсорного управления и мобильного рендера.

Исходную Windows-версию в `InkBladeWin` не изменяем. Она остаётся рабочим
эталоном поведения до тех пор, пока Godot-версия не достигнет паритета.

## Почему GDScript для общего проекта

Игровой код в текущем репозитории написан на C#, но отрисовка жёстко связана
с WinForms/SkiaSharp, звук — с NAudio, а ввод — с Windows XInput. Эти части
всё равно нужно заменить на кроссплатформенные подсистемы Godot.

GDScript позволяет сразу использовать стандартные Android/Windows export
templates и Godot API без привязки к WinForms. Игровые правила и данные будут
общими, а платформенные различия ограничатся вводом, звуком, настройками
экспорта и небольшими элементами UI.

## План структуры

```text
godot/
  project.godot
  scenes/       # сцены и UI
  scripts/      # GameState, Player, Enemy, World
  render/       # Node2D/CanvasItem и чернильные примитивы
  input/        # действия, touch controls, gamepad
  audio/        # AudioStreamPlayer и синтезированные эффекты
  assets/       # шрифты, текстуры, иконки
```

Основное разрешение сохраняем 1280×720 с масштабированием и landscape-ориентацией.
Для Android добавляем виртуальные кнопки/стик, а действия игры остаются теми же,
что и на Windows: move, jump, attack, dash, heal, pause.

## Текущее состояние

В `godot/` уже есть запускаемый каркас общей версии: титульный экран, тестовая
комната, игрок, три типа противников, снаряды, атака, рывок, лечение, комбо,
пауза, экран смерти, отладочные хитбоксы и сенсорные кнопки. Отрисовка и
простые звуковые сигналы работают без внешних ресурсов.

## Этапы

1. Создать минимальную Godot-сцену и проверить экспорт на Windows и Android.
2. Перенести `GameState`, физику, игрока, врагов и мир без привязки к UI.
3. Перенести `Ink` через `CanvasItem._draw`, сохранив цветовую палитру и
   внутреннее разрешение.
4. Заменить NAudio/XInput на Godot AudioStreamPlayer и InputMap.
5. Добавить touch UI, safe area, паузу при сворачивании и проверку FPS на
   физическом Android-устройстве.
6. Сверить тестовую комнату с Windows-эталоном и затем включить Android в CI.

## Альтернатива

Если принципиально сохранить максимум C#-кода, можно выбрать MonoGame. Он
официально поддерживает Android, но потребует собственного слоя примитивов,
UI, touch input и аудио. Godot C# тоже возможен, однако Android-экспорт C# в
документации Godot помечен как experimental, поэтому для первого общего
проекта выбран GDScript.
