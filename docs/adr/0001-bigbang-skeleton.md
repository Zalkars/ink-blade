# ADR 0001. Big-bang по архитектуре, walking skeleton по поставке

**Дата:** 28.10.2026
**Статус:** принято

## Контекст

В опросе выбраны одновременно «переписать всё сразу» (big-bang) и «сначала собрать играбельный каркас» (walking skeleton). Формально это противоположные стратегии: big-bang означает долгий период без рабочей сборки, skeleton — минимальную работающую версию как можно раньше.

## Решение

Разделяем два измерения.

- **Архитектура:** `game.gd` не рефакторим по кускам. Новая основа строится рядом, в ветке `refactor/foundation`. Монолит остаётся нетронутым.
- **Поставка:** первый коммит новой основы — играбельный скелет (меню → уровень → движение/атака → чекпоинт → save/load → пауза → выход).

`main` остаётся рабочей сборкой. Тег `prototype-reference` на `12ded74` фиксирует эталон ощущений.

## Последствия

- Старый прототип доступен для A/B-сравнения и не мешает новой структуре.
- Через 1–2 недели есть запускаемая сборка, а не «полгода тишины».
- Дублирование кода на время перехода — осознанная цена.
- Порт текущей комнаты как `arena_legacy` нужен для сравнения ощущений.

## Что считаем нарушением

- Правки `game.gd` «по мелочи» в ветке `refactor/foundation`.
- Долгая работа без запускаемой сборки.
