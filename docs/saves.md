# Сохранения — схема и правила

**Статус:** работает в каркасе: автосейв, чекпоинт, память об убитых врагах, сюжетных триггерах и открытом оружии
**Связано:** `docs/tech-brief.md` §11

---

## 1. Где лежат

```
user://saves/auto.json       — автосейв (пока единственный рабочий слот)
user://saves/auto.json.bak   — предыдущая версия, если запись уже была
user://saves/<slot>.json     — ручные слоты, зарезервировано под меню профиля
```

`user://` на Windows — `%APPDATA%\Godot\app_userdata\Ink Blade`. Формат — JSON, чтобы сохранение можно было прочитать глазами и починить руками.

Запись атомарная: сначала `auto.json.tmp`, потом переименование поверх `auto.json`, старая версия уходит в `.bak`. Если игра упадёт посреди записи, целым останется либо старый, либо новый файл, но не «половина».

## 2. Схема

```json
{
  "version": 2,
  "saved_at": 1762300000,
  "level": "ch01_hall",
  "checkpoint": "cp_mid",
  "killed": ["e1", "e3"],
  "triggers": ["archivist"],
  "weapons": ["weapon.blade", "weapon.brush"],
  "weapon": "weapon.brush",
  "hp": 5,
  "enemies_left": 2,
  "cleared": false
}
```

| Поле | Что значит |
|---|---|
| `version` | Версия схемы. Если сейв новее игры — предупреждение, а не краш |
| `saved_at` | Unix-время записи |
| `level` | ID уровня |
| `checkpoint` | ID пройденного чекпоинта, `""` — точка входа |
| `killed` | ID спавнов, которых уже нет в мире |
| `triggers` | ID сюжетных сцен, которые уже случились |
| `weapons` | Открытые карточки оружия, по порядку `order` |
| `weapon` | Оружие в руках на момент записи |
| `hp` | Здоровье на момент записи |
| `enemies_left` | Сколько врагов осталось (для отладки и будущего экрана слотов) |
| `cleared` | Уровень пройден |

Версия 1 (до чекпоинтов) читается: `SaveGame.migrate()` добавляет `checkpoint` и `killed` со значениями по умолчанию. Старые сейвы версии 2 без `triggers` и `weapons` тоже читаются: триггеры считаются непройденными, а игрок получает только клинок. Если такой сейв сделан уже после Переписчика, кисть придётся получить заново — для среза это допустимо.

---

## 3. Когда пишется

- старт уровня;
- касание чекпоинта (игрок лечится до полного);
- смерть врага;
- срабатывание сюжетного триггера (до показа диалога);
- выдача оружия после диалога;
- зачистка уровня.

Ручного сохранения пока нет: оно появится вместе с меню слотов.

---

## 4. Что помнит мир

1. **Чекпоинт** — где появляться после смерти.
2. **Убитые враги** — они не возрождаются после смерти игрока.
3. **Сюжетные триггеры** — разговор с Переписчиком не повторяется после продолжения.
4. **Оружие** — открытая кисть и выбранное оружие переживают смерть и перезапуск.

Позиция игрока внутри уровня, подобранные предметы и открытые двери появятся вместе со следующими этапами. Для них уже есть место: `killed` и `triggers` — списки такого рода, остальные добавятся рядом.

Босс в сохранение не входит: после смерти игрока он появляется заново с полным здоровьем и первой фазой. Призванные им кляксы тоже не сохраняются — это временные участники боя, а не расстановки уровня.

Временные враги вообще не попадают в `killed`: дети деления (`split_*`), призывы босса (`summon_*`) и отладочный спавн (`spawn_*`). Иначе файл рос бы от каждого прыжка кляксы, а после загрузки в нём висели бы ID, которых нет в уровне.

---

## 5. Смерть и продолжение

- Смерть → окно «Вы погибли» → «С чекпоинта» читает автосейв и собирает уровень заново.
- «Заново» в паузе начинает уровень с начала и перезаписывает автосейв.
- На титуле пункт «Продолжить» появляется, только если автосейв существует и уровень не зачищен.
- Зачищенный уровень не продолжается с середины: «Продолжить» начнёт новый заход.
- После победы над боссом сначала играет финал, и только потом открывается окно «Уровень пройден». Финальная катсцена не возвращает в игру: она ведёт к окну зачистки.

## 6. Чего ещё нет

- Меню ручных слотов и профилей.
- Состояние мира для предметов и дверей (триггеры и оружие уже есть).
- Проверка контрольной суммы и защита от ручной правки файла.
- Синхронизация с облаком.
