# Сохранения — схема и правила

**Статус:** работает в каркасе: автосейв, чекпоинт, память об убитых врагах, сюжетных триггерах и открытом оружии
**Связано:** `docs/tech-brief.md` §11

---

## 1. Где лежат

```
user://saves/auto.json       — автосейв
user://saves/auto.json.bak   — предыдущая версия, если запись уже была
user://saves/<slot>.json     — три ручных слота: slot_1, slot_2, slot_3
```

`user://` на Windows — `%APPDATA%\Godot\app_userdata\Ink Blade`. Формат — JSON, чтобы сохранение можно было прочитать глазами и починить руками.

Запись атомарная: сначала `auto.json.tmp`, потом переименование поверх `auto.json`, старая версия уходит в `.bak`. Если игра упадёт посреди записи, целым останется либо старый, либо новый файл, но не «половина».

## 2. Схема

```json
{
  "version": 5,
  "saved_at": 1762300000,
  "level": "ch01_hall",
  "checkpoint": "cp_mid",
  "killed": ["e1", "e3"],
  "triggers": ["archivist"],
  "weapons": ["weapon.blade", "weapon.brush"],
  "weapon": "weapon.brush",
  "hp": 5,
  "soul": 80,
  "enemies_left": 2,
  "cleared": false,
  "finale_seen": false,
  "dead": false,
  "dialogue": {},
  "ink_marks": []
}
```

| Поле | Что значит |
|---|---|
| `version` | Версия схемы. Если сейв новее игры — предупреждение, а не краш |
| `saved_at` | Unix-время записи |
| `level` | ID уровня |
| `checkpoint` | ID пройденного чекпоинта, `""` — точка входа |
| `killed` | ID спавнов, которых уже нет в мире |
| `triggers` | ID сюжетных сцен, которые уже случились |
| `weapons` | Открытые карточки оружия, по порядку `order` |
| `weapon` | Оружие в руках на момент записи |
| `hp` | Здоровье на момент записи |
| `soul` | Накопленный ресурс лечения, от 0 до 99; у старых сохранений 0 |
| `enemies_left` | Сколько врагов осталось (для отладки и будущего экрана слотов) |
| `cleared` | Победа сохранена; незавершённый финал можно досмотреть |
| `finale_seen` | Финал досмотрен до конца |
| `dead` | Смерть: загрузка возвращает полное HP и нулевую душу |
| `dialogue` | `{ "id": "archivist", "line": 2 }` — текущая реплика незавершённого разговора; `{}` — разговора нет |
| `ink_marks` | Ограниченный список геометрии чернильных следов на физическом рельефе; частицы не сохраняются |

Следы имеют собственную версию формата: v2 хранит проверенные float32-координаты
в компактных строках base64, v1 с числовыми массивами также читается. Это сокращает
паузу сериализации, не меняя вид следов. Максимум — 1 024 отметки: при заполнении
заменяются самые старые. Живые капли ограничены 240 частицами. Коллайдеры из
сохранённых рисунков не создаются. В r2 фон и декоративные колонны не принимают
чернила; при загрузке старые следы повторно обрезаются по текущему рельефу.
При аварийном завершении без уведомления
о сворачивании последние ещё не записанные следы (до 0,75 секунды) могут потеряться.

Версии 1–4 читаются. `SaveGame.migrate()` добавляет недостающие поля и обновляет схему до версии 5. Поле `props` хранит стабильные ID собранных предметов текущего уровня и по умолчанию получает пустой массив. После восстановления мира игра сверяет пройденные диалоги с оружием. Если сохранена текущая реплика, разговор продолжается с неё, а кисть выдаётся после завершения. Отсутствующий или повреждённый основной файл читается из `.bak`. Корректная резервная копия сохраняется при следующей записи.

Активный слот выбирается на титуле в разделе «Сохранения». Сессия `--level` использует `user://qa/saves/`, а команды разработчика, меняющие мир обычной игры, переключают записи в `user://debug/saves/` до возврата на титул.

## 3. Когда пишется

- старт уровня;
- касание чекпоинта (игрок лечится до полного);
- смерть врага;
- начало диалога и каждый переход на следующую реплику (награда ещё не выдаётся);
- завершение диалога (повторная выдача уже открытого оружия не происходит);
- зачистка уровня и завершение финала;
- смерть игрока;
- появление чернильных следов (запись пакетами с интервалом 0,75 с);
- пауза, уход в меню, потеря фокуса/сворачивание и штатное закрытие приложения.

В паузе доступны три ручных слота. Выбранный слот синхронизируется с автосейвом. Новая система слотов в рамках этой доработки не добавлялась.

## 4. Что помнит мир

1. **Чекпоинт** — где появляться после смерти.
2. **Убитые враги** — они не возрождаются после смерти игрока.
3. **Сюжетные триггеры** — завершённый разговор с Переписчиком не повторяется; незавершённый открывается на текущей реплике.
4. **Оружие** — открытая кисть и выбранное оружие переживают смерть и перезапуск.

Позиция игрока внутри уровня, подобранные предметы и открытые двери появятся вместе со следующими этапами. Для них уже есть место: `killed` и `triggers` — списки такого рода, остальные добавятся рядом.

Босс в сохранение не входит: после смерти игрока он появляется заново с полным здоровьем и первой фазой. Призванные им кляксы тоже не сохраняются — это временные участники боя, а не расстановки уровня.

Временные враги вообще не попадают в `killed`: дети деления (`split_*`), призывы босса (`summon_*`) и отладочный спавн (`spawn_*`). Иначе файл рос бы от каждого прыжка кляксы, а после загрузки в нём висели бы ID, которых нет в уровне.

## 5. Смерть и продолжение

- Смерть → окно «Вы погибли» → «С чекпоинта» читает автосейв и собирает уровень заново с полным HP и нулевой душой. Это правило сохраняется и при закрытии приложения после смерти.
- «Заново» в паузе начинает уровень с начала и перезаписывает автосейв.
- Обычное «Продолжить» восстанавливает сохранённые HP и душу без бесплатного лечения. Позиция — пройденный чекпоинт.
- Чернильные следы восстанавливаются при продолжении, смерти и повторном запуске приложения; новый заход начинает чистый уровень.
- На титуле «Продолжить» доступно, пока уровень не зачищен или финал ещё не досмотрен.
- После прерывания финала победа сохраняется, а финал начинается с первого слайда. После досмотра финала «Продолжить» скрывается.
- После победы над боссом сначала играет финал, и только потом открывается окно «Уровень пройден». Финальная катсцена не возвращает в игру: она ведёт к окну зачистки.
