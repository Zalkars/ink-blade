# Чернильный клинок — технический бриф

**Статус:** утверждён 28.10.2026
**Прототип:** `0.2.0-godot`, коммит `12ded74`, тег `prototype-reference`
**Ветка разработки:** `refactor/foundation` (создана от `12ded74`)
**`main`:** остаётся рабочей сборкой, ломать её нельзя

---

## 1. Что делаем

Из точного порта «Чернильного клинка» на Godot — полноценная коммерческая игра:

- длинные уровни вместо одной комнаты;
- сюжет с катсценами и диалогами;
- больше механик: оружие, способности, движения;
- больше врагов и боссов;
- более проработанная графика и эффекты;
- конвейер, в котором новый уровень или враг добавляется данными, а не правкой кода.

Главная цель фундамента — не «переписать игру», а построить конвейер. Признак успеха: новый враг добавляется за 10 минут и без программиста, новый уровень — без правок кода.

---

## 2. Рамки проекта

| Параметр | Решение |
|---|---|
| Длительность | 4–6 часов |
| Уровней | 8–12 |
| Боссов | 3–5 |
| Оружие | 2–3, окончательно решается после вертикального среза |
| Способности | 4–6, решается после среза |
| Языки | русский; архитектура готова к добавлению других |
| Структура мира | линейные главы + гейты способностей |

**Гейт способности** — место, куда можно пройти только с определённой способностью. Возврат назад разрешён, порядок глав — нет.

---

## 3. Платформы и рендерер

- **ПК — основная платформа.** Windows-сборка обязана собираться на каждом этапе.
- **Android — «зелёный».** На каждом этапе: собирается + проходит smoke-тест. Полноценный QA на устройствах — позже.
- **ПК: Forward+**, **Android: Compatibility.**

Правило двух путей: **каждый визуальный эффект обязан иметь упрощённый вариант, работающий на Compatibility.** Forward+ только добавляет (свечение, постобработка, нормали), но ничего не требует. Иначе ПК-версия станет отдельным продуктом.

Стоимость: +15–20% времени на эффекты и отдельная проверка на обеих сборках. Принято осознанно.

---

## 4. Симуляция

- Один таймлайн: весь геймплей в `_physics_process`.
- `physics_ticks_per_second = 120`.
- Игрок — `CharacterBody2D`; константы движения и боевые тайминги сохраняются.
- Hitstop — локальный множитель скорости анимации/симуляции, не второй цикл.
- Кастомные `move_x`/`move_y` и статические массивы `solids`/`oneways`/`hazards` уходят.

Смешивать два таймлайна (свой `_step` и физику движка) запрещено.

---

## 5. Арт

- Персонажи и враги — спрайты/атласы (`Sprite2D`, `AnimatedSprite2D`).
- Фоны, декор, чернильные эффекты — процедурный `InkR`.
- Мир — `TileMapLayer` + `Parallax2D` + `Light2D`.
- Частицы — `GPUParticles2D`/`CPUParticles2D` там, где это уместно; splat/ghost/slash остаются ручными.
- `InkR` нужно разделить на world-space и screen-space: сейчас он рисует в экранных координатах, с камерой это сломается.

---

## 6. Сохранения

Структура — слотовая с самого начала:

- профиль;
- несколько слотов;
- автосейв (отдельно от ручных слотов);
- состояние мира: флаги, убитые боссы, собранное, открытые двери, разблокированные способности.

В вертикальном срезе работает **один слот + автосейв**; остальные слоты включаются вместе с меню профиля. Схема при этом уже слотовая — иначе миграция.

Формат: JSON в `user://saves/`, с версией схемы, атомарной записью и бэкапом.

---

## 7. Локализация

- Сейчас — только русский.
- Источник остаётся JSON (`godot/locale/`), но ключи проектируются под будущий `TranslationServer`: пространства имён `ui.*`, `dialogue.*`, `entity.*`, `level.*`.
- Конкатенация строк запрещена — только целые фразы с подстановками.
- `en.json` не поддерживается; удаляется из сборки, файл можно оставить как образец схемы.

---

## 8. Редактор

- Редактор уровней **отложен**: сначала 2–3 уровня руками.
- Схема контента проектируется сейчас — см. `docs/content-schema.md`.
- Позже — плагин к Godot Editor: палитра, `@tool`-превью, валидация, «New Level» из шаблона.
- In-game редактор — только если появится UGC.

## 9. Структура репозитория (целевая)

```
godot/
  content/
    entities/          # карточки врагов, пропов, триггеров
    levels/            # описания уровней
    aliases.tres       # переименования ID
    manifest.json      # генерируется при экспорте
  scenes/
    flow/              # GameFlow, SceneManager, загрузка
    level/             # уровень, камера, чекпоинты
    actors/            # игрок, враги, боссы
    props/             # статика и динамика
    ui/                # HUD, меню, диалоги
  scripts/
    core/              # autoload-сервисы
    systems/           # бой, сохранения, диалоги
    render/            # InkR, fx, шейдеры
  assets/
    fonts/             # .ttf
    sprites/           # атласы персонажей
    tiles/             # тайлсеты
```

## 10. Порядок работ

1. Заморозка прототипа — **сделано** (тег + ветка).
2. Шрифты и мёртвый код — быстрые победы, не блокируют остальное.
3. Walking skeleton: `GameFlow`, `SceneManager`, уровень, камера, `TileMapLayer`, игрок, враг, save-заглушка, HUD на `Control`, debug-консоль.
4. Схема контента: `EntityDef`, `PropDef`, `LevelData`, `EntityDatabase`, манифест, стабильные ID.
5. Сохранения: слот, автосейв, состояние мира, версия, миграции.
6. Порт текущей комнаты как `levels/arena_legacy` — эталон ощущений для A/B.
7. Вертикальный срез: 1 уровень 15–20 минут, 2 оружия, 3 врага, 1 босс, катсцена, диалог, save/load, 60 FPS.
8. После среза: плагин-редактор, арт-пайплайн, музыка, локализация истории.

**Big-bang по архитектуре, skeleton по поставке.** Старый монолит не рефакторим по кускам — новая основа строится рядом. Но первая же поставка должна запускаться и играться.

**Паритет ощущений не требуется.** Автор разрешил экспериментировать, поэтому `prototype-reference` — ориентир по поведению, а не эталон, которому нужно соответствовать до процента. Что меняем сразу: падение медленнее (гравитация ниже на 20–25%), прыжок выше на 10–15% (проверить после смены гравитации), рывок длиннее на 10–15%, небольшой кулдаун атаки (0,06–0,10 с), pogo не обязателен. Подробности — `docs/baseline/2026-10-28/feel.md`.

## 12. Что не делаем сейчас

- Не строим редактор.
- Не добавляем контент в текущий монолит.
- Не переписываем всё одним коммитом.
- Не меняем арт-пайплайн целиком.
- Не гонимся за 4K и тяжёлыми шейдерами.
- Не трогаем `InkR`, аудио-синтез и `fx.gd` без необходимости.
- Не смешиваем два таймлайна симуляции.
