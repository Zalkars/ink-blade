# Baseline-метрики — 28.10.2026

Снято до перехода на новую основу. Нужно, чтобы потом сравнивать не «на глаз».

## Условия замера

| Параметр | Значение |
|---|---|
| Сборка | запуск проекта, Godot 4.7.2 console, не экспорт |
| Рендерер | `gl_compatibility` |
| Окно | 1280×720 (viewport), vsync включён |
| Разрешение кадра | 1920×1080 (масштаб Windows) |
| Сцена | титульный экран → тренировочная зала |
| Длительность | 16 с, замер раз в секунду |

Окно было не в фокусе — цифры FPS занижены относительно обычной игры. В записи автора проекта на той же сборке видно 44–64 FPS. Поэтому числа ниже — **относительная точка отсчёта**, а не паспорт производительности.

## Цифры

| Метрика | Титульный экран | Игровой экран |
|---|---|---|
| Средний FPS | 21–44 | **27,4** (мин. 19, макс. 37) |
| Draw calls | 40 | **506** (макс. 663) |
| Примитивы | 2 591 | **8 697** |
| Время `_process` | ~43 мс | **~61 мс** |
| Время физики | ~0,2 мс | **0,16 мс** |
| Память (static) | 44,6 МБ | 47,8 МБ |
| Видеопамять | 40,2 МБ | 42,9 МБ |
| Объектов | 1 628 | 1 633 |

## Что из этого следует

1. **Физика почти бесплатна** — 0,16 мс на кадр. Переезд на `CharacterBody2D` и 120 Гц не ударит по производительности. Узкое место — не физика.
2. **Узкое место — отрисовка.** 500 draw calls и 8,7 тыс. примитивов на одну комнату — это ручной `InkR`, который каждый кадр заново строит полигоны. Отсюда и 60 мс в `_process`.
3. **Одна комната уже на пределе.** Восемь-двенадцать уровней с десятком врагов на таком подходе не поедут. План «персонажи — спрайтами, фон и эффекты — `InkR`» подтверждается цифрами, а не вкусом.
4. **Бюджет для среза:** держать ≤ 300 draw calls и ≤ 16 мс в `_process` на игровом экране.

## Ограничения замера

- Замер через временный автозагрузочный скрипт (удалён после снятия), ввод эмулировался.
- Не измерены: время загрузки уровня, пиковая память за длинную сессию, поведение на Android.
- FPS на титульном экране скачет из-за запекания текстур в первые секунды.

## Как повторить

Проект не содержит CLI-флагов для автозапуска, поэтому замер делается временным автозагрузочным скриптом:

1. Добавить `Probe="*res://scripts/_probe.gd"` в `[autoload]`.
2. Запустить `Godot_v4.7.2-stable_win64_console.exe --path godot`.
3. Через 16 с скрипт печатает `SUMMARY` и выходит.
4. Удалить скрипт и строку автозагрузки.

Скрипт замера в репозиторий не входит намеренно: он одноразовый и не должен попасть в сборку.
