# Ink Blade 0.5.0 «Конвейер»

**База** — релиз 0.4.5, `main`, `1e1c197`. Проект Godot 4.5.1 находится в `InkBladeAndroid/godot`, папка `InkBladeAndroid` — корень репозитория. Windows x64 и Android используют GL Compatibility. Все пути в плане указаны от корня репозитория.

На этой базе в изолированных профилях прошли `smoke` (128 проверок) и `progress_regression` (74 проверки). Остальные наборы входят в исходный прогон перед реализацией.

## Цель и границы

Новый уровень добавляется через JSON, сцену-обёртку и запись в индексе. Новый экземпляр пикапа добавляется в JSON уровня, а новая карточка пикапа с поддерживаемым поведением — через `.tres` и сцену. Headless-валидатор обнаруживает ошибки данных до экспорта. Работу конвейера показывает `test_gallery`, отдельная тестовая комната.

В 0.5.0 входят один тип пропа (`pickup`), один пикап (`prop.soul_shard`) и одна тестовая комната. Двери, движущиеся платформы, редактор уровней (0.6.0), арт-пайплайн, новые главы, боссы и способности остаются за рамками релиза. Физика и бой сохраняют текущие параметры и симуляцию на 120 Гц. Лимит кадров 60/120 Гц, сенсорное управление, переход к финалу и оптимизации отрисовки и автосохранений из 0.4.5 должны сохраниться.

## Порядок работ

1. Зафиксировать исходное состояние на 0.4.5 и добавить реестр уровней.
2. Добавить пикап и совместимую миграцию сейвов.
3. Добавить манифест и валидатор.
4. Добавить тестовую комнату, сквозные проверки и проверить экспорт.
5. Перестроить главное меню, уточнить портрет и взаимодействие со снарядами.
6. Расширить консоль, диагностические экраны и панель разработчика.
7. Обновить документацию и метаданные релиза.

Каждый этап заканчивается импортом и затронутыми проверками. Autoload регистрируется после появления его скрипта.

### 1. Реестр уровней и загрузка

- Добавить `godot/content/levels/index.json` версии `1`. Поля верхнего уровня — `version`, `first`, `levels`. Запись уровня содержит `id`, `scene`, `data`, `order` и необязательный флаг `qa_only` (по умолчанию `false`). `first` задаёт первый сюжетный уровень. `order` задаёт порядок выдачи списка.
- Внести `ch01_hall` и `arena_01` с текущими ID, путями и содержимым. Первым оставить `ch01_hall`. Явно задать `data_path` в обеих сценах-обёртках, в том числе в `arena_01.tscn`, которая сейчас использует значение по умолчанию из `level.gd`.
- Добавить `LevelData` как типизированный адаптер индекса и JSON. Данные мира (`bounds`, `spawn`, `solids`, `one_ways`, расстановки, чекпоинты, триггеры и прочие существующие поля) остаются в JSON уровня. Загрузку и базовый разбор формата `LevelData` использовать из `level.gd` и валидатора. Сохранить прямой запуск сцен по `data_path`. `index.json` задаёт маршрут загрузки, `data_path` нужен для прямого запуска. Валидатор сверяет оба пути и `id` внутри JSON.
- Зарегистрировать `LevelDatabase` как `LVL`. API — `get_level(id)`, `ids()`, `first_id()`, `has(id)`. Заменить `LEVELS` и `FIRST_LEVEL` в `game_flow.gd`, а также зависимость `console.gd` от `flow.LEVELS` и статический список в справке команды `level`. Сохранить `level <id>` для обычных уровней, `warp x y`, `--play`, новую игру, продолжение, рестарт и финал. В обычной сессии `qa_only` скрыт из списка консоли и недоступен для загрузки через неё.
- `Godot --path godot -- --level <id>` запускает указанный уровень без вступления. Валидный `--level` включает отдельное хранилище `user://qa/saves/` до первой работы со слотами. Автосейв, ручные слоты, резервные копии, продолжение, смерть и фоновая запись используют это хранилище до конца процесса. Обычный запуск продолжает использовать `user://saves/`. Пустой или неизвестный ID выводит предупреждение и оставляет игру на титуле без записи нового сейва. При одновременном `--play` приоритет у `--level`.
- Разрешать уровень и сцену до очистки текущего мира, смены активного слота или копирования ручного сейва в `auto`. Если уровень из сохранения отсутствует или недоступен в текущем режиме, сообщить об этом и оставить исходный слот на месте. Пользователь может явно начать новую игру. Если индекс непригоден для запуска, оставить титул и вывести понятную диагностику.
- Существующее поле `name` остаётся запасным названием. Для новых уровней можно использовать `display_name_key`, который проверяется в обеих локалях. Границы камеры по-прежнему выводятся из `bounds`.

### 2. Пикап и сохранения v5

- Добавить `PropDef` с полями `id`, `kind`, `scene`, `version`, `display_name_key` и `soul_amount` для поддерживаемого пикапа. `PropDatabase` (`PDB`) загружает `.tres` из `content/props/` при запуске из исходников, а в экспорте читает секцию `props` манифеста по образцу `DB` и `WDB`. Реестр выдаёт карточку по ID и список ID.
- Создать `prop.soul_shard` со значением `soul_amount = 10`. Использовать процедурную графику и существующий HUD-тост с ключом в `ru.json` и `en.json`. Формат необязательного массива `props` в JSON уровня:

  ```json
  { "props": [{ "id": "shard_1", "def_id": "prop.soul_shard", "x": 640, "y": 480 }] }
  ```

- `id` экземпляра стабилен и уникален среди пропов этого уровня. Перемещение пикапа сохраняет его ID. Координаты задают точку у пола, как у врагов. Подбор происходит при контакте живого игрока в рамках физики. Повторные сигналы контакта не начисляют душу повторно. Пикап расходуется и при полной шкале. Душа ограничивается диапазоном 0–99. Тост о подборе использует название предмета.
- Поднять `SaveGame.VERSION` до `5`. `props` в сейве — массив ID собранных экземпляров текущего уровня (`level`). При миграции v4 добавляется пустой массив, существующие поля сохраняются. Сохранить чтение более ранних версий через текущую цепочку миграций. Слот с будущей версией диагностировать до записи или миграции. При старте нового забега список собранного пуст, при продолжении и возрождении он восстанавливается до спавна пропов. Правило сброса души после смерти сохраняется.
- Добавить состояние пропов в снимок и проверку изменений автосохранения. Подбор помечает прогресс для записи после обновления ID и души. Учитывать подбор при полной шкале, когда душа не изменилась. Использовать существующие отложенную запись, фоновый writer, `.tmp` и `.bak`.

### 3. Валидатор и манифест

- `godot/tools/build_manifest.gd` генерирует `content/manifest.json` детерминированно. Сохранить совместимые секции `entities` и `weapons`, добавить `levels` и `props`. Учитывать пути и хеши индекса, сцен уровней, JSON уровней и карточек. Для текстовых файлов нормализовать переводы строк перед хешированием. При ошибке сканирования генератор завершает работу с кодом `1` и сохраняет предыдущий манифест целиком.
- `godot/tools/validate_content.gd` запускается через `--script` и только читает файлы. Генератор и валидатор используют общий расчёт ожидаемого манифеста. Валидатор сравнивает его с сохранённым и сообщает об устаревании, включая удалённые записи. Код `0` означает отсутствие ошибок, `1` — ошибку. Диагностика содержит путь, поле или ID и причину.
- Проверить типы обязательных полей и версии JSON индекса и уровней, уникальность ID и `order`, доступность `first`, соответствие записи индекса сцене и JSON, а также существование ресурсов. Проверить дубликаты ID в карточках и среди экземпляров внутри каждой секции уровня. Проверка карточек опирается на исходные файлы, чтобы дубликаты, отброшенные при загрузке реестра, всё равно обнаруживались.
- Проверить ссылки на врагов с учётом существующих алиасов, пропы, награды оружия и диалоги. Проверить координаты спавна, врагов, пропов, чекпоинтов и триггеров относительно `bounds`. Ключи `speaker` и `text` из диалогов, `text` из катсцен и `display_name_key` из уровней и пропов должны присутствовать в секции `strings` обеих локалей (`ru.json` и `en.json`). Для зон ключи выводятся по `zones[].id`, как в текущем `game_flow.gd` (`BANNER_TITLE` и `BANNER_SUB` для `threshold`, `zone.<id>.title` и `zone.<id>.sub` для остальных). Литерал `name` в старом уровне остаётся допустимым. Неиспользуемые карточки и лишние файлы в каталогах контента можно вывести как предупреждения.
- Положить фикстуры в `godot/tests/fixtures/content/`. Аргумент `-- --root res://tests/fixtures/content/<case>` накладывает файлы фикстуры на дерево проекта по относительным путям. Остальной контент берётся из проекта. На каждый случай проверять код выхода и конкретную диагностику. Минимальные случаи — неизвестный `def_id`, дубликат ID, отсутствующая сцена или несовпадение `data_path`, пропущенный ключ локали и устаревший манифест.

### 4. Тестовая комната и экспорт

- Добавить `test_gallery.json`, `test_gallery.tscn` и запись `qa_only: true` в индекс. В комнате есть пол, 2–3 платформы, чекпоинт, один противник и один `soul_shard`. Убийство демонстрационного врага оставляет комнату доступной для проверки пикапа и продолжения. Сюжетные заставки в комнате не запускаются.
- Добавить `godot/tests/content_pipeline.tscn`. Через обычную загрузку мира проверить спавн, реальный физический контакт, однократное начисление, ограничение на 99, подбор при 99 и отсутствие собранного пикапа после чтения сохранения. Проверить новый забег, возрождение и миграцию v4 на примере с чекпоинтом, оружием, прогрессом мира и душой. Выполнить CLI-проверки загрузки `test_gallery` и невалидного `--level`, подтвердить, что обычный `auto` и ручной слот не изменились. Тест заканчивается итогом `CONTENT_PIPELINE_RESULT=OK` и кодом `0` при успехе.
- Проверить, что тесты и инструменты исключены из экспорта, а индекс, JSON, манифест, сцены и ресурсы доступны в пакете. Запустить экспорт Windows с `-- --level test_gallery` и подтвердить загрузку комнаты и пикапа через `PDB` из манифеста. Для Android собрать APK и проверить состав пакета. При доступном устройстве проверить холодный старт и продолжение сохранения v4. В отчёте отдельно указать, какие проверки выполнены на устройстве.

### 5. Главное меню, портрет и снаряды

- Главный экран Ink Blade ведёт в «Играть», «Сохранения», настройки и выход. Из референсов Dead Cells взять иерархию меню и отдельный экран слотов с видимым активным слотом. Пейзаж, графика, типографика и подсветка остаются в стиле Ink Blade.
- «Играть» открывает «Продолжить» (если в выбранном слоте есть незавершённая игра), «Нормальный режим» с подтверждением перезаписи и «Показать обучение». Отдельный экран сохранений показывает прогресс и дату, позволяет выбрать активный слот. Переключение слота и просмотр обучения сохраняют игровой прогресс. Навигация работает с клавиатуры, геймпада, мыши и сенсорного экрана.
- Убрать размытый двойной штрих с портрета на титуле, сохранить живой шарф и чёткие детали при 720p и 1080p.
- Вражеские снаряды проходят сквозь игрока во время рывка и сохраняют движение. Обычные попадания, столкновения с уровнем и истечение времени жизни работают по текущим правилам. Удары игрока воздействуют на врагов и проходят сквозь снаряды. Закрепить это регрессией боя.

### 6. Консоль и панель разработчика

- Сохранить F3 для консоли. Подсказки по командам и аргументам берутся из одного списка со справкой. Стрелки выбирают подсказку, Tab подставляет её, Enter исполняет строку. Для истории используются стрелки при пустом списке подсказок. Ошибочные числа и аргументы диагностируются до изменения состояния.
- F1 — справка, F2 — хитбоксы, F4 — панель разработчика, F5 — производительность, F6 — игрок и карта. F11 и F12 сохраняют полноэкранный режим и скриншоты. Панель доступна и из меню паузы для сенсорных экранов и геймпада.
- Панель использует те же команды, что и консоль. Секции «Игрок», «Карта», «Диагностика» дают доступ к полёту и его скорости, бессмертию, возрождению, смертельному урону, точным значениям здоровья и души, координатам, врагам, частицам, односторонним платформам и фону.
- Изменение игрового состояния через панель или консоль запускает отладочную сессию с изолированной записью. Отладочные переключатели сбрасываются при выходе на титул. Отключение врагов не засчитывается как победа, отключение частиц сохраняет читаемость атак.

## Проверки

Запускать из `InkBladeAndroid`. Перед тестами, которые работают с `user://`, задать свой `APPDATA` и `LOCALAPPDATA` в дочерней сессии PowerShell, например с отдельными каталогами под `.godot-user/`. Smoke и проверки прогресса изменяют и очищают слоты. Использовать отдельный профиль для каждого параллельного запуска. Для каждой команды сверять её ожидаемый результат и код выхода. CLI-проверка с `--quit-after` также должна дать строку `LEVEL test_gallery`.

```powershell
$inkBladeGodot = (Resolve-Path '../.tools/Godot_v4.5.1-stable_win64_console.exe').Path
& $inkBladeGodot --headless --path godot --import
& $inkBladeGodot --headless --path godot --script res://tools/build_manifest.gd
& $inkBladeGodot --headless --path godot --script res://tools/validate_content.gd
& $inkBladeGodot --headless --path godot tests/smoke.tscn
& $inkBladeGodot --headless --path godot tests/combat.tscn
& $inkBladeGodot --headless --path godot tests/fixes.tscn
& $inkBladeGodot --headless --path godot tests/controls.tscn
& $inkBladeGodot --headless --path godot tests/mobile.tscn -- --touch
& $inkBladeGodot --headless --path godot tests/progress_regression.tscn
& $inkBladeGodot --headless --fixed-fps 120 --path godot tests/traverse.tscn
& $inkBladeGodot --headless --path godot tests/balance.tscn
& $inkBladeGodot --headless --path godot tests/content_pipeline.tscn
& $inkBladeGodot --headless --path godot --quit-after 300 -- --level test_gallery
```

Сохранить проверки релиза 0.4.5 без ослабления существующих утверждений. Число проверок сравнивать с исходным прогоном, новые результаты фиксировать по фактическому выводу. Визуальные сценарии `capture`, `combat_capture`, `windows_review`, `ui_review`, `mountain_floor` и `perf` запускать в обычном окне. При экспорте использовать временные выходные пути и уже настроенные шаблоны и инструменты платформ. Подписание и публикация — отдельные действия релиза.

## Приёмка

- Обычная игра и консоль работают с реестром, текущие ID уровней и поведение сюжетного прохождения сохранены. Появление `test_gallery` требует только контентных файлов и записи индекса.
- Пикап добавляет до 10 души, исчезает один раз и остаётся собранным после чтения сейва. Сохранения v4 и более ранних поддерживаемых версий читаются. CLI-запуск использует отдельное хранилище и не меняет обычные слоты.
- Валидатор проходит на основном контенте, даёт ожидаемый код и причину для каждой фикстуры, повторная генерация манифеста даёт тот же результат.
- Экран сохранений выбирает активный слот, а обучение возвращает в меню без записи прогресса. Консоль подставляет команды и аргументы через Tab, F-клавиши открывают отдельные диагностические режимы, панель доступна с клавиатуры и из паузы.
- Проверены резкость героя на титуле при 720p и 1080p, пролёт снаряда сквозь рывок, обычный урон от попадания и прохождение удара оружием сквозь снаряд.
- Пройдены исходные и сквозные тесты. Экспорт Windows запускает `test_gallery` и загружает пикап из манифеста. APK собран и проверен на наличие контента. Результаты проверки на Android-устройстве указаны отдельно.
- Документация описывает фактическое поведение, а версия и заметки релиза согласованы с пресетами Windows и Android.
