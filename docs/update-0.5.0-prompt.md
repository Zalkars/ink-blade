# Промпт для исполнителя · Ink Blade 0.5.0 «Конвейер»

Реализуй обновление 0.5.0 по [плану `docs/update-0.5.0.md`](update-0.5.0.md). Прочитай план целиком: он задаёт контракты данных, порядок работ, проверки и критерии приёмки.

## Перед началом

- Найди корень репозитория `InkBladeAndroid`, проверь состояние рабочей копии, базовый коммит и пути к Godot. На момент подготовки плана база — 0.4.5 (`1e1c197`), движок — `../.tools/Godot_v4.5.1-stable_win64_console.exe` от корня репозитория. Сохрани пользовательские изменения и проверь применимые инструкции проекта.
- Посмотри `godot/project.godot`, `godot/export_presets.cfg`, `docs/content-schema.md`, `docs/levels.md`, `docs/saves.md`, `docs/tech-brief.md`, `docs/RELEASE_NOTES_v0.4.5.md`, `game_flow.gd`, `console.gd`, `level.gd`, `save_game.gd`, `entity_database.gd`, `weapon_database.gd` и `build_manifest.gd`. Для стиля проверок и схемы сейва смотри `godot/tests/smoke.gd` и `godot/tests/progress_regression.gd`.
- Зафиксируй результаты исходных проверок на 0.4.5. Запускай тесты с отдельными `APPDATA` и `LOCALAPPDATA`, поскольку они очищают слоты и меняют настройки.

## Реализация

1. Реестр уровней и совместимость обычной загрузки, включая консоль и старые сейвы.
2. Карточки пропов, `soul_shard`, сохранения v5 и изолированное хранилище запуска `--level`.
3. Генератор манифеста, валидатор и негативные фикстуры.
4. `test_gallery`, сквозные проверки и экспорт Windows/Android.
5. Титул, отдельный экран сохранений, повтор обучения, портрет и снаряды.
6. Консоль с подсказками, диагностика по F-клавишам и панель разработчика.
7. Документация, ADR, версии и заметки релиза.

После каждого этапа импортируй проект и прогони затронутые проверки. Регистрируй autoload вместе с его скриптом. Переиспользуй текущие пути загрузки, механику души, HUD-тосты и фоновый автосейв. Соблюдай стиль GDScript проекта и кодировку UTF-8.

Границы релиза указаны в плане. Храни результаты экспорта и тестовые профили отдельно от игровых данных и релизных артефактов. Пользуйся временными путями для выходных пакетов. Вне области правок находятся `godot/legacy/`, `native/`, `builds/`, `.tools/`, файлы веб-прототипа, `ses_*.json` и `.git`. Используй Git для чтения состояния и проверки diff. Коммиты, подпись и публикация выполняются только по отдельному запросу.
