# Godot-проект · v0.4.1

Актуальные инструкции запуска, управления и экспорта — в [README репозитория](../README.md).
Главная сцена: `scenes/flow/game_flow.tscn`. Настройки управления:
`scripts/ui/control_settings.gd`, сенсорный слой: `scripts/ui/mobile_controls.gd`.

> Разделы ниже описывают также исторический прототип `main.tscn` / `game.gd`.
> Его меню и ограничения ввода не относятся к текущему GameFlow.

# Ink Blade — Godot-порт (Windows + Android)

Полный 1:1 порт игры Ink Blade (C#/WinForms/SkiaSharp, `InkBladeWin/ink-blade-main`)
на Godot 4. Откройте эту папку в Godot 4.5.1 (GL Compatibility) и запустите основную сцену проекта (`scenes/flow/game_flow.tscn`).

## Архитектура

Внутреннее разрешение — 1280×720 (stretch `canvas_items`, aspect `ignore`),
холст заполняет весь экран без боковых рамок, а сенсорные координаты учитывают
масштабирование по ширине и высоте,
ориентация `sensor_landscape` на Android.
FloorY = 620, спавн игрока (300, 574). На Android включена
`sensor_landscape`-ориентация (orientation = 4) и immersive mode.

ПК- и Android-сборки используют один код, но расходятся по платформе:
`game.gd` вычисляет `mobile = OS.has_feature("android") or OS.has_feature("mobile")`
и строит список настроек (`_build_settings_items()`). На ПК это разрешение,
полный экран и VSync, на Android — сенсорные кнопки. Сенсорный слой
(`touch_mode`, `CTL.touch_enabled`) на ПК выключен всегда, даже если у машины
есть тачскрин; мышь не используется вообще.

### Чернильный рендер — `scripts/ink.gd` (автокласс `InkR`)

Всё рисование идёт через статический класс `InkR` — прямой аналог `Ink.cs`:
`text / line / poly / fill_poly / rect / blob / circle / arc / taper_arc /
ellipse_shadow / hatch / radial_glow / radial_rect / paper / stage / title /
vignette` и т.д. Важно: аргументы позиционные, как в оригинале, например
`text(s, x, y, size, font_kind, align, color2, a, spacing, ghost, baseline)`.

Палец-джиттер, «звёздный» шум и dash-линии совпадают с C# версией;
seed = `xorshift32((n*2654435761) ^ (boil*0x9e3779b1))`, где `boil = int(realTime*10)`.

### Запекание статики

Большие статичные картинки запекаются через `SubViewport` + `InkBakeNode`
(`bake_node.gd`, поля `w/h` и `fn: Callable`), порядок критичен:

1. `paper` (1280×720);
2. `stage` (1480×900, PAD=80 — داخل `InkWorld.bake_stage`, включая пыль);
3. `title` (1280×720, рисует поверх tex_paper).

Каждое запекание ждёт два `RenderingServer.frame_post_draw`, затем читает
`get_image()` и создаёт `ImageTexture`.

### Автолоады

- `L10N` (`i18n.gd`) — локализация: JSON-словари из `locale/`, `t(key, args)`,
  `next_lang()`, `prev_lang()`, `set_lang()`, `lang_name()`, `audit()`. Новый
  язык — это новый файл, правки кода не нужны.
- `SND` (`audio_ink.gd`) — порт `Audio.cs`: синтез на `AudioStreamGenerator`
  (22050 Гц), класс `SNDCore`, voice-и (tone/noise), ambient drone + wind,
  `ui()`/`ui_confirm()`/`hit()`/`unlock()`/`set_muted()`. Буфер вывода — 0.09 с
  (~90 мс): при 0.35 с звук отставал от картинки. Микшер отдаёт кадры одним
  `push_buffer` за `_process`, а не `push_frame` на каждый сэмпл.
- `CTL` (`input_ink.gd`) — порт `Input.cs`: собственный ввод без Input Map,
  класс `INKCtl`. `CTL.update(dt)` вызывается один раз за кадр, все подшаги
  симуляции (шаги ≤ 1/120 с guard < 10) видят одни и те же edges.

  - Клавиатура — словарь текущих назначений `keyboard` (действие → массив
    кодов клавиш), значения по умолчанию — `DEFAULT_KEYBOARD`. Проверка идёт и
    по логическому, и по физическому коду (`_key_down`), поэтому раскладка не
    важна.
  - Геймпад: XInput→Godot маппинг через
    `PAD_BUTTON_JOY = [0,1,2,3,9,10,-1,-2,4,6,7,8,11,12,13,14]`
    (-1 = LT ось 4, -2 = RT ось 5), данные прямым опросом `Input`,
    deadzone 0.32 c ремапом; вибрация — `start_joy_vibration` + `vibrate_handheld`.
    Назначения — `pad_map` (действие → массив слотов XInput), по умолчанию
    `DEFAULT_PAD`. Действие `back` (B, слот 1) закреплено за выходом из меню:
    `CTL.back()` = `pause` или `back`, поэтому из любого экрана можно уйти с
    геймпада. B нельзя переназначить другому действию.
  - Тач: зоны `TOUCH_ZONES`/`TOUCH_LABELS` единый источник в `game.gd`,
    multitouch по pointer-id; для UI-навигации — `CTL.touch_tap(action)`
    (отложенный edge), удержание — `touch_enter/touch_exit` с refcount.
    События тача принимаются, только если `CTL.touch_enabled` (выставляется
    `_apply_touch_mode()` и истинно лишь в Android-сборке).

### Локализация

Все строки интерфейса — в `locale/*.json` с полями `name` (название языка на
нём самом), `order` (порядок в переключателе) и `strings` (ключ → текст).
Автолоад `L10N` сканирует каталог при запуске, поэтому для нового языка
достаточно скопировать `ru.json` в `<код>.json` и перевести значения.

Если ключ пропущен, берётся русский вариант; в debug-сборке печатается
предупреждение, полный отчёт даёт `L10N.audit()`. Выбор языка хранится в
`user://settings.cfg` (`[locale] lang`). После смены языка `game.gd`
перезапекает `stage` и `title` — в этих слоях есть текст. В обоих пресетах
экспорта прописан `include_filter="locale/*.json"`, иначе JSON не попадёт в
PCK.

### Игровые скрипты

- `game.gd` — порт `Game.cs`: состояния title/play/paused/dead, combat
  (pogo, дефлект снарядов, хитстоп), hazard-телепорт, комбо, баннер, экраны
  паузы/управления/смерти/отладки, оркестрация запекания, тач-UI.
- `world.gd` (`InkWorld`) — физика, платформы, hazard-зона, свечи, пыль,
  трава и `bake_stage`.
- `player.gd` (`InkPlayer`) — порт `Player.cs`.
- `enemy_base.gd` + `grunt/sentry/dummy/enemy_bolt` — враги; у подклассов
  метод называется `draw()` (не `_draw()`).
- `hud.gd` (`InkHud`) — душа, рывок, комбо, баннер, подсказки, панели.
- `fx.gd` (`InkFx`) — частицы, спарки, кольца, shake/flash/damage-оверлеи.

## Управление

Клавиатура: A/D — движение, Пробел/Z — прыжок, J/X — атака, K/SHIFT — рывок,
L/V — лечение, ESC — пауза и «назад», ENTER — подтверждение, R — заново, M — звук,
F1 — управление, F2 — хитбоксы, F11 — полный экран, F12 — скриншот.
Геймпад: стик — движение, A/X/B/Y, LB/RB/LT/RT, START — пауза, B — назад.
Тач: плавающий стик слева и большие виртуальные кнопки A/X/B/Y, Ⅱ справа
(только в Android-сборке). Сенсорные зоны работают с несколькими пальцами
одновременно, автоматически переводятся из координат окна в логический холст
1280×720 и остаются доступны на титульном экране, в паузе, в окне управления и
после смерти. Мышь не обрабатывается: `InputEventMouseButton` в `game.gd`
игнорируется, а эмуляция тача/мыши в `project.godot` отключена.

### Настройки

Строки экрана настроек собираются в `_build_settings_items()` по платформе.
ПК: язык, звук, тряска, вибрация, полный экран, разрешение, VSync, отладка,
управление, назначения, назад. Android: те же пункты, но вместо трёх
графических — «Сенсорные кнопки». Панель (`_settings_panel()`) считает высоту
от числа строк, поэтому оба списка помещаются без прокрутки.

- `RESOLUTIONS` — 1280×720 … 3840×2160; индекс хранится в
  `settings.cfg` → `[display] resolution`.
- `_apply_display()` применяет режим окна, размер и VSync (на Android —
  no-op). `_toggle_fullscreen()` (F11) меняет тот же флаг, что и пункт меню.
- `_step_setting()` обрабатывает `←`/`→` (разрешение и язык), подтверждение
  работает как «вперёд».

### Назначения клавиш и кнопок

Экран `submenu == "bindings"` (Настройки → «Назначения клавиш») — это отдельный
подрежим `_update_bindings`/`_render_bindings` в `game.gd`.

- Список действий — `CTL.BINDABLE`; клавиатурная колонка правит
  `CTL.keyboard[action]`, геймпадная — `CTL.pad_map[action]` (слоты XInput).
- Захват ввода идёт в `game.gd::_input`: клавиша берётся по
  `physical_keycode` (fallback `keycode`), JoyButton переводится в слот через
  `CTL.slot_of_joy()`, триггеры (оси 4/5) — в слоты 6/7. Пока идёт захват,
  `_handle_global()` молчит, чтобы новая клавиша не сработала как горячая.
- `CTL.set_key()`/`CTL.set_pad()` забирают код у других действий; если для них
  это была последняя клавиша, `_spare_key()` подбирает свободную (Esc не
  выдаётся никогда).
- Esc зарезервирована: её нельзя назначить другому действию, и она всегда
  остаётся в `keyboard["pause"]` и `keyboard["back"]`. Так же B (слот 1)
  закреплена за `pad_map["back"]`. Поэтому из любого экрана можно выйти назад
  с клавиатуры и с геймпада.
- Навигация по экрану без перескоков: `↑`/`↓` идут от первой строки до
  «Сбросить всё», затем до «Назад» и упираются в края; на двух нижних кнопках
  `←`/`→` переключают между ними. `_bind_reset_index()`/`_bind_back_index()`
  задают их позиции.
- START или B во время захвата отменяют его (`_handle_bind_capture`), не
  дожидаясь таймера.
- Движение на геймпаде фиксировано (стик/D-pad), его геймпад-колонка только
  отображается.
- «Сбросить всё» вызывает `CTL.reset_bindings()`. Раскладка сохраняется в
  `user://settings.cfg`, секция `[bindings]` (`key_<action>`, `pad_<action>`).
- Памятка (`_render_controls`) и подсказки экранов строятся из
  `CTL.label_key()`, `CTL.label_move()`, `CTL.label_pad()`, а для строк
  подсказок — из `_hint_label(action)`/`_back_hint()`; тексты подсказок в
  локали содержат `%s` и заполняются этими подписями, поэтому после
  переназначения они остаются правдивыми. Локализованные названия действий —
  ключи `ACT_*`, тексты экрана — `BIND_*`.

## Экспорт

Пресеты в `export_presets.cfg`: Windows (`builds/InkBlade-Windows.exe`) и
Android debug APK (arm64 + armeabi-v7a, пакет `org.inkblade.game`,
разрешение VIBRATE). Готовый проверенный debug APK лежит в
`../builds/InkBlade-debug.apk`. Для публикации нужен release keystore и AAB.

### Оформление актёров и платформ

Сцены `scripts/actors` используют рисование персонажа, гончей и ока из
`v0.2.0-godot`. Адаптеры `scripts/visuals` передают только состояние для
отрисовки: движение, урон, оружие и столкновения остаются у текущих актёров.
Шарф обновляется отдельной визуальной симуляцией; после телепорта сбрасывается.
Новые кляксы и Хранитель используют ту же бумажную заливку и чернильный контур.

`Level` рисует сплошные поверхности через `InkWorld.platform`, включая цепи
односторонних платформ. `TileMapLayer` продолжает задавать коллизии; его
атлас скрыт, а границы рисования округляются к той же сетке 32 px.

Кадры проверки можно сохранить командой:
`Godot --path godot tests/capture.tscn -- --output-dir=res://../builds/visual-review`.
Без аргумента кадры сохраняются в `user://captures/`.


### Сенсорное управление текущей версии

В `GameFlow` подключён `scripts/ui/mobile_controls.gd`: на Android он включается
автоматически. На ПК тот же интерфейс можно проверить аргументом `--touch`.

- Слева — плавающий стик с мёртвой зоной. Справа — A (прыжок), X (атака),
  B (рывок), Y (удерживать для лечения) и отдельная кнопка смены оружия.
- Удержание X повторяет атаки; B делает один рывок на нажатие. Каждый палец
  захватывает свою кнопку до отпускания: стик, прыжок и удар работают одновременно.
- Круглые кнопки сохраняют оформление v0.2: тушь, светлый неровный контур и
  буквенные обозначения. Добавлены подписи, плавный отклик и индикаторы
  восстановления рывка и накопления лечения.
- Меню выбираются касанием строки; катсцены и диалоги листаются касанием.
  Перетаскивание и отменённые касания не подтверждают пункты меню.
- Пауза, смерть, смена экрана и сворачивание сбрасывают удержания. Сворачивание
  ставит игру на паузу. Системная кнопка Android «Назад» открывает/закрывает паузу.
- `aspect=expand` сохраняет пропорции на широких экранах. HUD, меню и кнопки
  учитывают безопасную область Android, включая вырезы и системные панели.

Проверка: `Godot --headless --path godot tests/mobile.tscn -- --touch`.
Без `--headless` тест сохраняет кадры в `builds/mobile-review/`.
Проверка на физическом устройстве всё ещё нужна для оценки удобства и FPS.


### Настройка управления в текущем GameFlow

«Настройки» доступны в главном меню и в паузе. Экран
`scripts/ui/control_settings.gd` поддерживает мышь, сенсорный ввод,
клавиатурный фокус и стандартную навигацию Godot с контроллера.

- **Клавиатура и мышь:** выберите действие, затем нажмите клавишу или
  кнопку мыши (левая, правая, средняя, боковые). По умолчанию левая кнопка
  атакует, правая выполняет рывок. Захват отменяется Esc или через 8 секунд.
  Конфликтующее назначение заменяется с сохранением доступности действия;
  Esc закреплена за паузой и возвратом. Мышь в меню работает с пунктами меню.
- **Контроллер:** переназначаются кнопки и триггеры. Для движения можно
  выбрать стик, крестовину или оба; мёртвая зона регулируется от 10 до 60%.
  Крестовина зарезервирована за движением. B / START возвращают из настроек.
- **Сенсорное:** плавающий стик, фиксированный стик либо крестовина
  с диагоналями. Непрозрачность регулируется от 25 до 100%. В редакторе
  перетаскивается каждый элемент, включая движение и паузу; размер каждого
  регулируется от 65 до 150%. Редактор доступен и на ПК для предпросмотра.
  Перекрывающиеся элементы нельзя сохранить. «Отмена» восстанавливает
  расположение до редактирования. Позиции хранятся относительно безопасной
  области экрана и ограничиваются её границами.

Назначения и параметры сохраняются автоматически в `user://settings.cfg`;
редактор расположения применяет изменения кнопкой «Сохранить».
«Сбросить раздел» возвращает исходные значения только текущей вкладки.
Остальные секции файла настроек сохраняются.

Проверка: `Godot --headless --path godot tests/controls.tscn`.
Для проверки мультитача: `Godot --headless --path godot tests/mobile.tscn -- --touch`.
Без `--headless` тест настроек также сохраняет снимки в
`builds/controls-review/`. Тест настроек восстанавливает исходный settings.cfg.
